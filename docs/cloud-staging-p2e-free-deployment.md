This deployment plan is based on release commit `ab9bb67517ac2512839dbde4574242fae4d8ad9d` plus an isolated Cloud Staging read-only auth fix on branch `codex/cloud-staging-p2e-readonly-deploy-20261107`. Neither `main` nor the pinned release branch should be merged or force-pushed by this runbook.

**Current acceptance:** Supabase staging project `dqctxaoaxhtqtgmtsysk` has three applied Prisma migrations, 19 application tables, and 18 synthetic records: 4 roles, 2 users, 3 categories, 3 locations, 3 items, 3 stock balances, 215 total on-hand. The source of these numbers is independent, read-only SQL. Never rerun seed or migration as part of Render builds. The protected Windows UAT database at `127.0.0.1:5433` is out of scope.

## Pre-deployment gates (must PASS before provisioning)

- **ZERO PAID:** Review Render workspace billing/payment method, bandwidth and build limits, and spending ceiling. Do not create the service if costs above $0 are possible under the operator's policy; do not add a payment method or turn on paid features.
- **HOBBY ELIGIBILITY:** Get explicit operator confirmation that this Vercel project is solely personal/non-commercial before creating a Hobby project (see Vercel Terms of Service).
- **SOURCE/CHECKS:** Use only this branch, review the read-only login patch, verify GitHub CI and require no merge to `main`.
- **CLOUD SECURITY:** Confirm Supabase Data API exposure separately in dashboard; allow no public table privileges or permissive RLS policies. DB-backed authentication is the sole allowed staging POST route. No live data.
- **SECRETS:** Operator enters `DATABASE_URL` directly in Render Dashboard. Use the Supabase project's session pooler 5432 and SSL; the URL must encode special characters in the password. Render Blueprint generates a secure `JWT_SECRET`. Never put passwords, JWTs, API keys or .env files in Git, build logs, chat, PRs or reports.
- **FRONTEND DOMAIN:** `CORS_ORIGIN` must be the exact, HTTPS frontend origin, without path, wildcard or trailing extra suffix.
- **FREE-only guard:** If a provider requests billing/paid plan, STOP. Resource creation is not an authorization to buy services.

## Backend: Render Free Blueprint

The root `render.yaml` creates **one** Node Web Service on the **free** plan, region Singapore. Automatic deployment is **off**. It uses the exact feature branch and the monorepo root.

- Build: `npm ci --include=dev && npm run prisma:generate && npm run build:shared && npm run build:api`
- Start: `npm run start --workspace=@acm/api`
- Health: `GET /api/v1/health/readiness` – unlike `/health`, this returns 503 if DB is disconnected.
- Cloud profile: `NODE_ENV=production`, `ACM_DEPLOYMENT_PROFILE=cloud_staging`, `STAGING_READ_ONLY=true`, `ALLOW_STAGING_AUTH_LOGIN=true`.
- `DATABASE_URL` and `CORS_ORIGIN` require secure manual entry at Blueprint creation. `JWT_SECRET` is generated by Render. Do not invoke `prisma migrate deploy` as build/start/hook: migrations were completed earlier.

Do not expose Render publicly until the readiness endpoint returns 200 with `database: connected`. If the first deployment fails, inspect logs **without disclosing secrets** and fix the cause; don't blindly redeploy or change paid settings.

## Frontend: Vercel Hobby (conditional)

Only if the operator confirms **personal/non-commercial** usage, and the Vercel GitHub integration sees `acmhtql-sys/ACM_QLLK`, create **one** project in Vercel team ACM on the Hobby plan. Use:

- Git branch: `codex/cloud-staging-p2e-readonly-deploy-20261107`. Do not deploy default `main` accidentally. Ensure production branch is this branch or explicitly select its preview deployment and verify the commit.
- Root Directory: `.` (monorepo, not `apps/web`). The web app imports the sibling `@acm/shared` workspace.
- Framework: Vite; Install: `npm ci`; Build: `npm run build:shared && npm run build:web`; Output Directory: `apps/web/dist`.
- `VITE_API_BASE_URL=https://<REAL_RENDER_HOSTNAME>/api/v1`. Use the actual assigned Render hostname, not an example.
- `VITE_ENABLE_LOCATION_WRITES=false`, `VITE_ENABLE_STOCK_TRANSACTION_WRITES=false`, `VITE_ENABLE_STOCK_ADJUSTMENT=false`.
- The existing root `vercel.json` provides SPA rewrites, including on direct link refresh.

After obtaining the real Vercel URL, set Render `CORS_ORIGIN=https://<REAL_VERCEL_HOSTNAME>` and manually deploy/restart as needed. Do not use wildcard CORS.

## Acceptance – no write operations

1. `GET https://<REAL_RENDER_HOSTNAME>/api/v1/health/readiness` returns HTTP 200 and `database: connected`.
2. `GET https://<REAL_RENDER_HOSTNAME>/api/v1/health` reports the service; note this route returns HTTP 200 even if DB is down, so it is not an adequate sole readiness check.
3. Open the actual Vercel URL and log in using the operator-held synthetic staging password for `staging-admin@acm.internal`. The Cloud Staging login exception reads user records, returns signed JWT, and **must not** update `failedLoginAttempts`.
4. Verify exactly three tagged inventory items and total on-hand = 215. No actual data.
5. Verify writes are rejected with HTTP 403 and code `STAGING_READ_ONLY_BLOCKED` on ordinary mutation endpoints; do not send legitimate write payloads merely to test blocking.
6. Verify the counts `users=2`, `items=3`, `balances=3`, `onHand=215` are unchanged after login and smoke checks.
7. Verify the Supabase Data API using a valid publishable/anon API key where permitted; invalid-key 401 alone does **not** prove public-table access is blocked. Never publish the key.
8. The Cloud Postgres archive `ACM_CLOUD_STAGING_20261107_021026.dump` was format-verified but has NOT undergone an isolated restore drill. Restore only to a disposable local target (never UAT 5433 or the live Cloud staging database).

## Failure protocol

- **No paid resources. No main merge. No local UAT access.**
- On CI failure: stay on the review branch; fix in a new commit, never force-push.
- On Render/Vercel configuration failure: keep the service disabled or undeployed; no unverified claim of live readiness.
- On database error: do not reseed, migrate or reset Supabase; collect redacted evidence and stop.
